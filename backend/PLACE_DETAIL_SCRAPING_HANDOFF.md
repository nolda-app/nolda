# 업체 상세정보(전화번호/영업시간/메뉴) 스크래핑 — 작업 인계 문서

`PLACE_DATA_PIPELINE.md`의 최종 병합 스키마에서 **미구현**으로 남아있는
`phone`(상세), `business_hours`, `menu` 컬럼을 채우기 위한 작업 정리.
셀레니움이 설치된 다른 환경에서 이어서 진행하기 위해 지금까지 확인/합의된
내용을 정리한다.

## 1. 배경 — 공식 API로는 불가능함을 확인함

네이버 개발자센터 지역검색 API 공식 문서
(`developers.naver.com/docs/serviceapi/search/local/local.md`) 응답 필드를 직접 확인:

| 필드 | 상태 |
|---|---|
| title, link, category, description, address, roadAddress, mapx, mapy | 정상 제공 |
| **telephone** | 문서에 "값을 반환하지 않는 요소. 하위 호환성을 유지하기 위해 있는 요소입니다"라고 명시 — 즉 필드는 있지만 네이버가 절대 채우지 않음 |
| **영업시간, 메뉴** | 필드 자체가 문서에 없음 |

NCP(네이버 클라우드 플랫폼) Maps 제품군(Geocoding/역지오코딩/Directions/정적지도)도
좌표·주소 변환용이라 업체 상세정보는 원천적으로 제공하지 않음.

**결론: phone/business_hours/menu는 공식 API 경로가 없고, 스크래핑 외엔 방법이 없음.**

## 2. 스크래핑 난이도 확인

`pcmap.place.naver.com` 상세페이지에 브라우저 헤더 없는 단순 `curl` 요청을
**1회** 보냈더니 즉시 다음과 같이 차단됨:

> "과도한 접근 요청으로 서비스 이용이 제한되었습니다" (요청 IP까지 응답에 노출)

→ JS 미실행 + 브라우저다운 헤더(Accept-Language, Sec-Fetch-*, 쿠키) 부재를
기준으로 요청 1건만에 봇으로 판정하는 것으로 보임. 실제 Chrome을 띄우는
**셀레니움이면 이 1차 필터는 통과할 가능성이 높지만**, 차단 메시지가
"과도한 접근"이라고 명시한 걸 보면 동일 IP의 요청 빈도 자체도 감시 대상일
가능성이 있어 대량 순회 시 다시 막힐 수 있음.

→ 그래서 **658곳 전체가 아니라 실제로 화면에 노출되는 코스 장소만** 우선
대상으로 좁히기로 함 (아래 3번).

## 4. 진행 방식 (합의된 방향, 아직 미실행)

1. **정찰 먼저** — 실제 상세페이지 DOM을 아직 못 봤음(이 환경은 브라우저 확장 미연결).
   위 25곳 중 1곳만 셀레니움으로 열어 렌더링된 HTML을 덤프하고,
   전화번호/영업시간/메뉴가 어떤 선택자에 있는지부터 확정할 것.
   (참고: 상세페이지는 `pcmap.place.naver.com/<category>/<placeId>/home` 형태의
   iframe 기반 SPA로 보임 — 검색 결과에서 진입해 placeId를 얻어야 함)
2. **본 스크래핑** — 확정된 선택자로 25곳 순회.
   - 업체당 5~15초 랜덤 딜레이 (사람처럼)
   - 차단 문구("과도한 접근"/429 등) 감지 시 **그 즉시 전체 중단** — 재시도로
     뚫으려 하지 말 것. IP/프록시 로테이션, 캡차 우회 같은 탐지 회피는 하지 않기로 함.
   - 진행 중 결과는 매 건마다 CSV에 append (중간에 멈춰도 그때까지 결과는 남게)
3. **산출물**: `backend/data/place_details_selenium.csv`
   | 컬럼 | 설명 |
   |---|---|
   | pid | 위 목록의 pid (기존 `places_mapo.csv`의 `id`와 매칭) |
   | phone | 전화번호 |
   | business_hours | 영업시간 원문 (추후 가공해서 jsonb 스키마로 변환 필요) |
   | menu | 메뉴 원문 (문화/전시관 대상은 공란) |
   | status | ok / blocked / not_found 등 |
   | scraped_at | 수집 시각 |
4. `backend/requirements.txt`에 `selenium` 추가 필요 (Selenium 4+ 내장 드라이버
   매니저 사용 — 별도 chromedriver 설치 불필요, Chrome 앱은 이미 설치돼 있음 확인함).

## 5. 이후 처리 (이 문서 범위 밖)

- `place_details_selenium.csv` → `nolda-장소가공.ipynb`(또는 신규 스크립트)에서
  `places_mapo.csv`와 pid 기준으로 병합해 `phone`/`business_hours`/`menu` 컬럼 채우기.
- `business_hours`는 최종적으로 `jsonb` 스키마(요일별 구조 등)로 정규화 필요 — 원문 그대로
  저장했다가 별도 파싱 단계에서 처리하는 편이 안전함(팝업 파이프라인의 날짜 파싱과 유사).

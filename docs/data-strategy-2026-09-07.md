# 2026-09-07 데이터 수집·분석 전략 확정

카드/사진 기반 자동 취향 분석([2026-09-04 회의](meeting-2026-09-04.md)에서 방향만 정한 부분)을 실제로 어떻게 수집·분석할지 조사·확정.

## 데이터 수집 방법

한국에서 개인 프로젝트 수준으로 오픈뱅킹/마이데이터 API(카드사 직접 연동)는 금융위 인가가 필요해 불가능. 대신 **사용자 업로드 기반**으로 확정.

| 소스 | 방법 |
|---|---|
| 카드 내역 | 카드사 앱 이용내역 화면 스크린샷 업로드 → Claude Vision API로 가맹점명·금액·날짜 OCR 추출. (문자 내역 캡처도 대안이지만 스크린샷 쪽이 UX상 더 간단) |
| 사진첩 | PWA는 갤러리 자동 접근 불가 — `<input type="file" multiple accept="image/*">`로 사용자가 직접 선택 → EXIF(위치·시간) 추출 + Claude Vision으로 이미지 내용 분석 |

## 분석 로직: 빈도/카테고리 → 이탈도(anomaly) 기반

초기 분석은 "카페 결제가 몇 % 많다" 식의 빈도·카테고리 기준으로 취향을 추정했으나, 문제 발견: 평일 점심 국밥·분식, 매일 아침 커피처럼 **생계형/루틴성 소비**가 "취향"으로 잘못 분류됨.

**전환한 기준**: 반복되고 예측 가능한 소비는 "루틴"으로 제외, 드물고 예측을 벗어난 소비를 "진짜 취향 신호"로 채택.

- **루틴 판정**: 빈도 높음 + 금액 변동 적음 + 특정 시간대 고정 (예: 매일 08시 커피, 정기 교통비 충전, 평일 점심 분식)
- **취향 신호 판정**: 빈도 1~2회 + 금액 변동 큼 + 저녁/심야 시간대 (예: 오락실·PC방 심야 지출, 평소 없던 셀프케어 지출)

즉 "얼마나 자주" + "평소 대비 얼마나 특이한 금액/시간인지"를 점수화 — 오락실·PC방·심야 고액 지출류가 자동으로 상위권에 뜨고, 점심 분식/커피/교통비는 자동으로 걸러지는 구조.

> 현재 `frontend/src/planner`의 목업 `analyze()`는 데모용 카테고리·빈도 기반 로직이다. 실제 백엔드 분석 파이프라인 구현 시 이탈도 기반으로 교체 필요.

## 장소 데이터: 네이버 검색 API (지역검색)

지도 렌더링/경로용 네이버 지도 API와는 별개로, 장소 후보 수집은 **네이버 검색 API — 지역 검색**(`https://naverapihub.apigw.ntruss.com/search/v1/local`) 사용.

```json
// GET .../search/v1/local?query=정자동 카페&display=2
{
  "items": [
    {
      "title": "스타벅스 정자점",
      "category": "카페,디저트>카페",
      "address": "경기도 성남시 분당구 정자동 159-3 SPG센터",
      "roadAddress": "경기도 성남시 분당구 정자일로 166 SPG센터 (정자동)",
      "mapx": "1271063108",
      "mapy": "373648752"
    }
  ]
}
```

## DB: `uploaded_data.analysis_json`

업로드(카드 스크린샷/사진) 건마다 분석 결과를 저장. 코스 추천 시 사용자의 최신 `analysis_json`들을 모아 AI 프롬프트에 넘긴다.

```json
{
  "source": "card",
  "spending": { "food": 45, "cafe": 25, "culture": 20, "activity": 10 },
  "price_tendency": "mid",
  "keywords": ["분위기 좋은", "소규모", "한식"],
  "analyzed_at": "2026-09-07T14:00:00Z"
}
```

## 확정된 데이터 흐름

1. **데이터 수집 → 추천**: 사용자가 카드 내역/앨범을 업로드하면 AI가 즉시 분석 → `analysis_json`에 저장 → 코스 추천 시 이 분석 결과를 그대로 사용
2. **장소 → 추천**: 네이버 검색 API로 마포구 장소를 호출 → AI가 `analysis_json`의 취향과 매칭해서 코스 구성
3. **추천 → 저장**: 완성된 코스를 AI Agent가 자동 저장

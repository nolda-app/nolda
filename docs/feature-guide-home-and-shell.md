# 구현 지침서 — 홈 화면 · 앱 껍데기 · 연동 유지

이 문서는 **앱의 바깥쪽**을 고칠 사람을 위한 것입니다. 첫 화면, 화면 사이 이동, 하단 탭바, 그리고 로그인·유튜브 연동이 화면 전환을 넘어 유지되는 방식을 다룹니다.

취향 분석·코스 생성·길안내의 내부 동작은 [구현 지침서 — 취향 분석](feature-guide-taste-and-navigation.md)을 보세요.

---

## 1. 화면 순서

```
앱 실행
  │
  ├─ 주소에 ?yt= / ?login_token= / ?course= 가 있으면 ──→ (아래 둘을 건너뜀)
  │
  ├─ [스플래시] 로고 1.2초
  ├─ [홈] ─ 탭바로 검색·저장·마이페이지
  │     ├─ "코스 만들기" 배너·버튼 ──→ 분석을 새로 시작
  │     └─ 탭바 "코스" ──────────────→ 만든 코스가 있으면 코스 목록, 없으면 분석부터
  │
  ├─ [로그인] 좌상단 홈 버튼으로 홈 복귀
  ├─ [데이터 선택] 유튜브·사진첩 고르기
  ├─ [분석 중] 카드 스와이프
  ├─ [취향 요약] 값 확정
  └─ [코스 목록] ←──탭바──→ [저장한 코스]
```

### 왜 스플래시와 홈을 건너뛰나

소셜 로그인과 유튜브 연동은 **구글로 나갔다가 우리 주소로 새로 들어옵니다.** 브라우저가 페이지를 통째로 새로 열기 때문에 앱 상태가 전부 초기화되고, 앱 입장에서는 "방금 실행된 것"과 구분되지 않습니다.

그대로 두면 연동을 마치고 돌아온 순간 스플래시 → 홈이 떠서 **진행 중이던 분석 흐름이 사라집니다.** 그래서 [`PlannerApp.tsx`](../frontend/src/planner/PlannerApp.tsx)의 `returning`이 주소의 표식을 보고 둘을 건너뜁니다.

```ts
const [returning] = useState(() => {
  const q = new URLSearchParams(window.location.search)
  return ['yt', 'yt_error', 'login_token', 'login_error', 'course'].some((k) => q.has(k))
})
```

**새 OAuth 연동을 추가하면 이 배열에 표식을 반드시 넣어야 합니다.** 빠뜨리면 그 연동만 홈으로 튕깁니다.

## 2. 하단 탭바

[`BottomTabs.tsx`](../frontend/src/planner/BottomTabs.tsx) 한 곳에만 있습니다. 홈과 코스 화면이 같은 컴포넌트를 쓰므로, 아이콘·순서를 바꾸면 양쪽이 함께 바뀝니다.

| 탭 | 홈에 있을 때 | 코스 화면에 있을 때 |
|---|---|---|
| 홈 | 맨 위로 스크롤 | 홈으로 나감 |
| 코스 | 코스 목록으로 나감 (분석 전이면 분석부터) | 코스 목록 |
| 검색 | 검색창 포커스 | 홈의 검색 탭으로 |
| 저장 | 저장한 코스 (홈 안) | 저장한 코스 (앱 안) |
| 마이페이지 | 마이페이지 | 홈의 마이페이지로 |

`active`가 `null`이면 아무 탭도 켜지지 않습니다. 탭에 대응하지 않는 화면에 있을 때 씁니다.

**저장 탭의 초록 점**은 `savedCount > 0`일 때만 붙습니다.

### 폭을 맞추는 규칙

탭바는 `position: absolute; left: 0; right: 0`이라 **가장 가까운 `position: relative` 조상의 폭**을 따릅니다. 그래서 화면 본체 `.pl-screen`과 그 바깥 껍데기 `.pl-app`이 **둘 다 같은 `max-width`** 를 가져야 합니다.

한쪽만 걸면 그 화면에서만 탭바가 혼자 길어집니다 (실제로 한 번 겪었음).

## 3. 모바일 프레임

모든 화면은 `max-width: 430px`(iPhone Pro Max 폭)로 가운데 정렬됩니다. PC 브라우저에서도 폰 앱처럼 보이게 하기 위함입니다.

폭을 바꿀 때는 [`planner.css`](../frontend/src/planner/planner.css)의 `430px`를 **전부 함께** 고쳐야 합니다. 현재 6곳입니다.

| 대상 | 클래스 |
|---|---|
| 화면 본체 | `.pl-screen` |
| 앱 껍데기 | `.pl-app` |
| 조건 시트 | `.pl-sheet` |
| 코스 상세 | (모달) |
| 진행 화면 시트 | `.pl-live-sheet` |
| 장소 소개 팝업 | `.pl-psheet` |

### 세로 크기

폰은 세로가 짧아서 **고정 px 높이는 화면 밖으로 밀려납니다.** 큰 요소는 `min(고정값, vh)` 형태로 적어 화면 높이에 따라 줄어들게 합니다.

```css
.sg-deck { height: min(380px, 52vh); }   /* 스와이프 카드 */
.sg-fan  { height: min(250px, 30vh); }   /* 카드 부채꼴 */
.ks      { min-height: min(640px, 76vh); } /* 키오스크 */
.pl-routemap { height: min(190px, 26vh); } /* 코스 상세 지도 */
```

`min-height`는 `100vh`와 `100dvh`를 나란히 적습니다. 모바일 브라우저 주소창 때문에 `100vh`가 실제 화면보다 커지는 문제를 `dvh`가 해결하고, `dvh`를 모르는 구형 브라우저는 앞의 `100vh`를 씁니다.

## 4. 홈 화면

[`HomeScreen.tsx`](../frontend/src/planner/HomeScreen.tsx)가 껍데기, [`HomeViews.tsx`](../frontend/src/planner/HomeViews.tsx)가 각 탭의 내용입니다.

```
NOLDA                          🔔 알림
[🔍 검색창]
┌──────────────────┐
│ 배너 (16:9, 자동) │  4.5초마다 전환
└──────────────────┘
🍚 ☕ 🍷 ✨ 🖼 🌳 🏃   카테고리 7개 (한 줄)
지금 가볼 만한 곳
[카드][카드][카드] →→   우→좌 자동 흐름
[ 내 취향으로 코스 만들기 ]
```

### 추천 장소 고르기

`pickPlaces()`는 **사진이 있는 장소만** 추린 뒤 종류별로 나눠 **한 종류씩 돌아가며** 뽑습니다. 그냥 랜덤으로 뽑으면 데이터가 많은 식사·카페가 화면을 채웁니다 (전체 963곳 중 식사 414 · 카페 203).

한 번 고른 목록은 `useMemo`로 고정합니다. 리렌더마다 다시 섞이면 흐르는 줄이 튑니다.

### 흐르는 줄

같은 목록을 **두 번 이어 붙이고** 절반만큼 미는 CSS 애니메이션입니다. 끝에 닿는 순간 처음과 같은 그림이라 이어져 보입니다.

- 커서를 올려도 멈추지 않습니다. 지나가다 멈추면 고장처럼 보입니다
- 시스템 '움직임 줄이기'를 켠 사용자는 애니메이션 대신 손으로 미는 가로 스크롤이 됩니다
- 뒤쪽 복제본은 `aria-hidden` — 화면 낭독기가 같은 장소를 두 번 읽지 않게

### 조정할 값

| 값 | 위치 | 뜻 |
|---|---|---|
| `MARQUEE_N` | `HomeScreen.tsx` | 흐르는 줄에 올릴 장소 수 (14) |
| `BANNER_MS` | `HomeScreen.tsx` | 배너 전환 간격 (4500ms) |
| `BANNERS` | `HomeScreen.tsx` | **더미 데이터.** 행사·광고 API가 생기면 이 배열을 응답으로 교체 |
| `46s` | `planner.css` `@keyframes pl-marquee` | 한 바퀴 도는 시간 |

### 아직 없는 것

알림, 알림 설정, 공지사항, 고객센터, 로그아웃은 **화면이 없어 안내 문구(토스트)만 뜹니다.** `HomeScreen.tsx`의 `soon()`입니다.

## 5. 장소 소개 팝업

`HomeViews.tsx`의 `PlaceSheet`. 홈 카드·검색 결과·카테고리 결과 어디서 눌러도 같은 팝업이 뜹니다.

기본 정보(이름·종류·주소·태그)는 이미 받아둔 장소 데이터에서 바로 그리고, **영업시간·전화·메뉴·1인 가격은 팝업을 연 뒤에** `GET /places/details`로 받아옵니다. 목록을 그릴 때 전부 받으면 느려지기 때문입니다.

상세를 못 받아도 기본 정보는 그대로 보입니다.

## 6. 연동 유지

### 로그인

JWT(30일)를 `localStorage`(`nolda:login-token`)에 두고, 앱을 열 때 `GET /auth/me`로 확인합니다.

**실패했다고 토큰을 지우면 안 됩니다.** 서버가 꺼져 있거나 네트워크가 끊긴 것뿐인데 지우면 멀쩡한 로그인이 날아갑니다. 개발 중 백엔드를 재시작할 때마다 로그인이 풀리던 원인이 이것이었습니다.

`fetchMe`는 실패할 때 서버 응답 코드를 `AuthFailure.status`에 실어 보냅니다. **401·403·404일 때만** 토큰을 지우고, 코드가 없으면(= 서버가 답을 못 줌) 그대로 둡니다.

#### 로그인 후 어디로 돌아가나

소셜 로그인은 페이지를 통째로 새로 열어서 "어디서 왔는지"가 사라집니다. 그래서 떠나기 직전에 `sessionStorage`(`nolda:after-login`)에 목적지를 적어둡니다.

| 어디서 눌렀나 | 값 | 로그인 후 |
|---|---|---|
| 홈 우상단 로그인 · 마이페이지 로그인 | `'home'` | 홈으로 복귀 |
| 코스 만들기 배너·버튼 · 코스 탭 | (지움) | 분석 화면 |

#### 계정 선택 화면을 강제하지 않는다

`auth.py`의 `google_login_url(switch_account=False)`가 기본입니다. `prompt=select_account`를 매번 붙이면 로그인할 때마다 계정을 고르게 돼 번거롭습니다. 붙이지 않으면 구글에 이미 로그인된 사람은 화면을 거치지 않고 바로 돌아옵니다.

계정을 바꿀 때만 `GET /auth/login/google?switch=1` — 로그인 화면의 "다른 구글 계정으로 로그인" 링크가 씁니다.

#### 닉네임이 '게스트'로 보인다면

`GOOGLE_SCOPE`에 **`profile`이 빠져 있으면** 구글이 이름·사진을 주지 않아 `nickname`이 빈 값이 되고, 프론트가 '게스트'로 대체합니다. 현재 값은 `openid email profile`입니다.

카카오는 `account_email`만 요청하므로 여전히 이름이 빕니다. 받으려면 카카오 개발자 콘솔에서 `profile_nickname`을 '사용함'으로 켜고 `KAKAO_SCOPE`에 추가해야 합니다.

`JWT_SECRET`은 `backend/.env`에 있어야 합니다. **없으면 소셜 로그인 자체는 성공해도 마지막 단계에서 실패합니다.** 이 값을 바꾸면 기존에 발급한 토큰이 전부 무효가 되므로, 팀원·배포 서버가 **같은 값**을 써야 합니다.

### 유튜브

집계 결과 id를 `localStorage`(`nolda:yt-id`)에 둡니다. 한 번 연동하면 **로그아웃 전까지 구글 동의를 다시 받지 않습니다.**

```
첫 연동:  구글 동의 → 백엔드가 집계 → ?yt=<id> → localStorage에 저장
다음부터: 저장한 id로 GET /youtube/taste/<id> 만 호출
로그아웃: id 삭제
```

⚠️ **결과는 백엔드 메모리에 있습니다** ([`youtube.py`](../backend/youtube.py) `_results`). 백엔드를 재시작하면 사라지고, 프론트는 "유튜브 연동이 만료됐어요"를 띄운 뒤 재연동 상태로 돌아갑니다. 개발 중에는 자주 겪습니다. 제대로 고치려면 집계 결과를 Supabase에 저장해야 합니다.

### scope가 바뀌었다는 오류

같은 구글 클라이언트 ID로 **로그인과 유튜브를 함께 쓰면서** 생긴 문제입니다. 유튜브 권한만 요청해도 구글이 이미 승인된 `email`·`openid`를 얹어 돌려주고 (`include_granted_scopes="true"`), oauthlib이 "요청한 scope와 다르다"며 토큰 교환을 거부해 **502**가 납니다.

`youtube.py`에서 `OAUTHLIB_RELAX_TOKEN_SCOPE=1`을 켜 이 검사를 완화했습니다. 권한이 줄어든 게 아니라 늘어난 경우이고, 그 추가 권한도 우리가 로그인용으로 받은 것이라 안전합니다.

### 구글 OAuth 환경변수 — 두 개는 서로 다릅니다

| 키 | 쓰는 곳 |
|---|---|
| `GOOGLE_LOGIN_REDIRECT_URI` | 소셜 로그인 (`auth.py`) |
| `GOOGLE_REDIRECT_URI` | 유튜브 연동 (`youtube.py`) |

이름이 비슷해 한쪽만 넣고 헤매기 쉽습니다. 둘 다 구글 클라우드 콘솔의 **승인된 리디렉션 URI**에 등록해야 합니다 — 단, 클라이언트 유형이 **웹 애플리케이션**일 때만 그 칸이 있습니다. 데스크톱 앱 유형은 `http://localhost/...` 루프백을 등록 없이 허용하므로 로컬에서는 동작하지만, **배포하면 반드시 웹 애플리케이션 클라이언트가 필요합니다.**

## 6.5 프로필 편집

마이페이지 **편집**에서 이름과 사진을 고칩니다. `PATCH /auth/me`.

- **이름** — 1~20자. 공백만 있으면 거부
- **사진** — 브라우저에서 **160px 정사각 JPEG**로 줄여 `data:` URL로 보냄 (`toAvatarDataUrl`). 짧은 변 기준 가운데를 잘라 얼굴이 덜 잘리게 함

### 왜 스토리지를 안 쓰나

Supabase Storage 버킷이 없어, 줄인 사진을 `users.avatar_url`에 글자로 그대로 넣습니다. 보통 10~20KB이고 서버가 200KB(`AVATAR_MAX_CHARS`)를 넘으면 거부합니다.

**MVP 규모에서는 충분하지만 오래 갈 방식은 아닙니다.** 사용자가 늘거나 원본 화질이 필요해지면 Storage로 옮기세요. 그때 `avatar_url`에 URL만 넣으면 되므로 **프론트는 고칠 필요가 없습니다.**

`avatar_url` 요청 값의 뜻:

| 보낸 값 | 결과 |
|---|---|
| 필드 없음 | 사진 그대로 |
| `''` | 기본 아바타로 되돌림 |
| `data:image/…` · `http(s)://…` | 그 사진으로 교체 |

### 로그아웃

마이페이지 하단. 실수로 누르면 손해라 **확인을 한 번** 받습니다. `toStart()`가 토큰·유튜브 연동·분석 상태를 모두 되돌리고, 화면은 홈에 머뭅니다.

저장한 코스는 `localStorage`에 있어 로그아웃해도 이 기기에 남습니다.

## 7. 코스 경로선

지도의 경로선은 원래 미리 만들어 둔 [`routes.ts`](../frontend/src/planner/routes.ts)에서 코스 id로 찾아 썼습니다. 그런데 그 파일에는 고정 코스 `c1`~`c10`밖에 없어서, **AI·DB로 만든 코스는 id가 없어 직선으로 그려졌습니다.**

이제 [`useWalkLegs.ts`](../frontend/src/planner/useWalkLegs.ts)가 `POST /walk/legs`로 실제 경로를 받아옵니다.

```
실제 경로 받기 → 실패하면 routes.ts → 그것도 없으면 undefined(지도가 직선으로)
```

백엔드 `walk.legs()`는 장소 N개를 이어 구간 N-1개를 만들고, 구간마다 기존 `route()`를 부릅니다. **격자 캐시와 하루 한도가 그대로 적용**됩니다.

⚠️ **TMAP 한도.** 코스 상세를 열 때마다 구간 수만큼 호출합니다 (장소 4개면 3건). 하루 한도는 `TMAP_DAILY_LIMIT`(기본 800), 무료 실제 한도는 1,000건입니다. 같은 코스를 다시 열면 20m 격자 캐시가 막아주지만, **캐시는 서버 메모리에만 있어 재시작하면 비워집니다.** 넘으면 조용히 직선으로 떨어지고 에러는 나지 않습니다.

## 7.5 지도에서 구간 하나만 보기

경로가 겹치는 코스는 선이 전부 같은 실선이라 어디서 어디로 가는 길인지 구분되지 않았습니다.
[`NaverMap.tsx`](../frontend/src/planner/NaverMap.tsx)에 두 값을 넘겨 해결합니다.

| 값 | 뜻 |
|---|---|
| `activeLeg` | 고른 구간 번호. `0`이면 1번째 → 2번째 장소 |
| `legOnly` | 켜면 고른 구간만 남기고 나머지 경로·핀을 **감춘다**. 끄면 회색 점선으로 **흐리게만** |

| | 고른 구간 | 나머지 |
|---|---|---|
| 색 | 브랜드 초록 | 무채색 `#9AA1A9` |
| 선 | 실선, 굵기 6 | 점선, 굵기 3 |
| 진하기 | 0.95 | 0.5 |

### 화면별 동작

- **코스 상세** — 지도 아래 `전체 / 1→2 / 2→3 …` 버튼. `legOnly`를 켜서 고른 구간만 남기고
  지도를 그 구간에 맞춰 확대한다. 같은 버튼을 다시 누르면 전체로
- **코스 진행 중** — `arrived`로 지금 걷는 구간을 자동 계산(`arrived - 1`). `legOnly`는 끈다.
  남은 코스가 안 보이면 앞으로 어디를 더 가는지 감이 사라지기 때문

### 지도를 다시 만들지 않는다

경로선 그리기는 지도 생성과 **별도 effect**입니다. 한 덩어리로 두면 구간을 바꿀 때마다
지도가 새로 만들어져 보던 위치와 확대가 초기화됩니다.

`fitBounds`도 **경로선 effect 한 곳에서만** 부릅니다. 고른 구간에 따라 맞출 범위가 달라지는데
두 곳에서 부르면 처음 열 때 깜빡입니다.

## 8. 이미 밟은 지뢰

### OAuth 복귀를 화면 상태보다 먼저 확인해야 한다

홈을 "실행하면 무조건 보이는 화면"으로 만들면, OAuth에서 돌아온 순간에도 그 규칙이 적용돼 진행 중이던 흐름을 덮습니다. 화면 상태의 **초기값**을 주소 표식으로 결정해야 하고, `useEffect`로 나중에 고치면 이미 한 프레임 깜빡입니다.

### 껍데기와 본체의 폭이 다르면 탭바만 길어진다

`.pl-screen`에만 `max-width`를 걸고 `.pl-app`에는 안 걸어서, 코스 화면에서만 탭바가 브라우저 전체 폭으로 퍼졌습니다. `position: absolute` 요소는 가장 가까운 `position: relative` 조상을 기준으로 삼는다는 점을 잊기 쉽습니다.

### 분석을 끝낸 상태(`done`)가 남아 분석 화면을 건너뛴다

"코스 만들기"를 눌렀는데 분석 화면 대신 코스 목록이 나오던 문제입니다. `restart()`로 분석 상태를 되돌려야 합니다. 반대로 **탭바의 코스 탭은 `restart()`를 부르면 안 됩니다** — 만들어 둔 코스를 지우게 됩니다.

### 로컬에서 되는 것과 배포된 것은 다르다

배포는 **GitHub에 올라온 코드**로 빌드합니다. 커밋·머지만 하고 push하지 않으면 내 컴퓨터에서만
동작하고 배포본은 옛 코드 그대로입니다. "로컬은 되는데 배포가 안 된다"의 가장 흔한 원인입니다.

`backend/.env`는 git에 올라가지 않으므로 **Render 환경변수는 따로 바꿔야 합니다.**
구글 클라이언트를 교체할 때는 순서가 중요합니다.

```
1. Render에 새 CLIENT_ID/SECRET 입력 → 재배포
2. 배포본에서 로그인 확인
3. 그 다음에 옛 시크릿 삭제   ← 먼저 지우면 배포본 로그인이 즉시 끊긴다
```

### 아이콘 획이 얇으면 작은 크기에서 흐려진다

`KindThumb`은 크기에 따라 `strokeWidth`를 정하는데, 카테고리 줄(46px)에서는 얇아 보입니다. CSS로 `.pl-home-cat .pl-thumb svg { stroke-width: 2.2 }`처럼 덮습니다. SVG의 `stroke-width` 속성은 CSS 속성으로 덮어쓸 수 있습니다.
